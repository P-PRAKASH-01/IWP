ABSTRACT

Modern digital apparel commerce requires an agile, highly accessible, and visually optimized web presence that empowers shoppers to discover garments seamlessly while facilitating rapid customer conversions. Monolithic e-commerce systems often impose heavy overhead, complex payment setup barriers, and high maintenance costs, whereas simple static websites lack centralized inventory administration, persistent enquiry tracking, and secure data access. This technical project report presents the engineering design, architecture, implementation, and deployment of a modern, cloud-native Responsive Garment Catalogue and Administrative Management Web Platform.

The platform transitions an apparel showcase from fragile, localized client-side storage (localStorage) into a decoupled architecture utilizing React 19, React Router 7, Vite 8, and Tailwind CSS 4 on the frontend, interfaced with Supabase BaaS (PostgreSQL 15, PostgREST API, Supabase Auth, and S3-compatible Object Storage). To optimize user conversion rates, the platform implements a hybrid conversational commerce model: customer enquiries are validated and transactionally persisted into PostgreSQL before launching an automated, pre-formatted order payload into WhatsApp Web/API. On the administrative tier, a protected management workspace empowers authorized personnel to execute real-time CRUD operations across products, hierarchical categories, banners, and store configuration, as well as triage enquiries with private internal notes and sanitized CSV export functionality.

Security is guaranteed via PostgreSQL Row Level Security (RLS) policies that enforce strict access boundaries at the database kernel level. The production frontend is compiled and hosted on Vercel's Global Edge Network with SPA deep-route rewriting.

Keywords: React 19, Single Page Application, Vite 8, Tailwind CSS 4, Supabase, PostgreSQL, Row Level Security, PostgREST, Conversational Commerce, WhatsApp API, Role-Based Access Control, Vercel Edge.

Chapter 1: Project Scope, Problem Definition & Objectives

1.1 Project Overview & Background

The garment and apparel manufacturing sector in regional hubs such as Tiruppur, India, is characterized by agile production cycles, diverse garment variations (crewneck t-shirts, polo shirts, hoodies, activewear), and direct customer relationships. While regional businesses maintain high manufacturing excellence, their digital reach has traditionally been constrained by cumbersome e-commerce tools or fragmented social media messaging that lacks structured product presentation.

This project engineers a modern, cloud-native Responsive Garment Catalogue and Administrative Management Web Platform for Sri Sai Garments. The application provides an engaging digital catalogue with instant multi-criteria filtering, product attribute visualization, sizing calculators, and direct WhatsApp enquiry pathways, backed by a robust cloud relational database and a protected administrative content management system.

1.2 Limitations of Legacy LocalStorage Architectures

In preliminary web prototypes, catalogue items and enquiry records were stored using browser-local storage (window.localStorage). Technical analysis identified critical architectural bottlenecks:

  • Client-Bound Data Isolation: Catalogue mutations made on an administrator's browser remained stored solely inside that specific browser profile, completely failing to synchronize with remote customers.
  • Absence of Central Administration: Updating prices, publishing seasonal collections, or modifying business contact details required editing source code files or manually redeploying bundles.
  • Insecure Demonstration Authentication: Prototypes used client-side hardcoded credentials and mock sessions, exposing administrative interfaces to simple DOM inspection.
  • Customer Privacy Risks: In unauthenticated client-side stores, submitted customer telephone numbers and internal notes were unencrypted and accessible via browser developer tools.

3.2 Conversational Commerce Flow Architecture

Unlike conventional e-commerce platforms that force customers through rigid shopping cart checkouts and third-party merchant accounts, this system implements a pre-validated conversational checkout pipeline.

The Two-Phase Enquiry & Handoff Pipeline
  1. Phase 1: Transactional Persistence: The customer completes the enquiry form. The client dispatches a validated payload to the Supabase enquiries table. PostgreSQL evaluates the insert policy (status = 'New' AND internal_notes = '') and commits the row.
  2. Phase 2: Conversational Handoff: Upon receiving confirmation (HTTP 201), the client executes buildWhatsAppUrl() in whatsapp.js, formatting product specifications, SKU, selected color swatch, size, quantity, and customer contact information into an encoded URI payload and launching https://wa.me/<digits>?text=<payload>.

3.3 Frontend Component & Routing Hierarchy

  • Public Routes: / (Home), /products (Catalogue & Filtering), /products/:id (Product Details), /about (About Us), /contact (Contact & Direct Enquiries).
  • Administrator Routes: /admin/login (Auth Entry), /admin/dashboard (Metrics Overview), /admin/products & /admin/products/new (Garment CRUD), /admin/categories (Taxonomy), /admin/enquiries (Customer Triage), /admin/content (Banners), /admin/settings (Store CMS).

4.3 Recursive SQL Stored Procedures

To resolve category visibility dynamically without costly client-side tree traversals, the database implements a Recursive Common Table Expression (CTE) SQL function: 

create or replace function public.is_public_category(category_uuid uuid)
returns boolean language sql stable security definer set search_path = '' as $$
  with recursive category_ancestors(id, parent_id, is_active) as (
    select category.id, category.parent_id, category.is_active
    from public.categories category where category.id = category_uuid
    union
    select parent.id, parent.parent_id, parent.is_active
    from public.categories parent
    join category_ancestors child on child.parent_id = parent.id
  )
  select exists (
    select 1 from category_ancestors where id = category_uuid and is_active
  ) and not exists (
    select 1 from category_ancestors where not is_active
  );
$$;

This procedure ensures that if a parent category (e.g., Men's Collection) is deactivated, all of its descendant subcategories and associated garment listings are automatically hidden from public API responses.

Chapter 5: Security Engineering & Access Control

5.1 Defense-in-Depth Security Model

The platform employs a four-stage defense-in-depth security model:

  • Client Tier: Form boundary validation, file MIME guards (JPEG/PNG/WebP/AVIF < 5MB), and route guards.
  • Network Tier: Strict TLS 1.3 encryption, HTTP Strict Transport Security (HSTS), and CORS policies.
  • API Gateway Tier: PostgREST authentication and JSON Web Token (JWT) cryptographic signature verification.
  • Database Kernel Tier: PostgreSQL Row Level Security (RLS) ensuring non-bypassable authorization boundaries.

5.2 Row Level Security (RLS) Policy Specifications

Target Entity Action Role Security Policy Condition
admin_profiles SELECT authenticated user_id = (select auth.uid())
categories SELECT anon, auth (select public.is_public_category(id)) OR (select public.is_store_admin())
categories ALL (C,U,D) authenticated (select public.is_store_admin())
products SELECT anon, auth (status = 'published' AND (select public.is_public_category(category_id))) OR (select public.is_store_admin())
products ALL (C,U,D) authenticated (select public.is_store_admin())
enquiries INSERT anon, auth WITH CHECK (status = 'New' AND internal_notes = '') (Blind Insert)
enquiries SELECT authenticated (select public.is_store_admin()) (Public access completely barred)
enquiries UPDATE/DEL authenticated (select public.is_store_admin())
product-media SELECT anon, auth bucket_id = 'product-media' (Public read for CDN delivery)
product-media ALL (C,U,D) authenticated bucket_id = 'product-media' AND (select public.is_store_admin())

5.3 Anti-Injection Defenses

1. SQL Injection Mitigation
All database transactions execute through the PostgREST ORM, which serializes query parameters into typed PostgreSQL queries, preventing SQL injection vulnerabilities.
2. CSV Formula Injection Defense
When exporting customer enquiries to CSV in AdminEnquiries.jsx, cell values are sanitized against spreadsheet formula execution: 
function csvValue(value) {
  const text = String(value ?? '');
  // Neutralize formula triggers (=, +, -, @, Tab, CR) by prepending a single quote
  const safeText = /^[	
=+\-@]/.test(text) ? `'${text}` : text;
  return `"${safeText.replaceAll('"', '""')}"`;
}

const calculateSizeFromChest = (chestInches) => {
  const val = parseFloat(chestInches);
  if (isNaN(val) || val <= 0) return '';
  if (val < 36) return 'XS';
  if (val < 38) return 'S';
  if (val < 40) return 'M';
  if (val < 42) return 'L';
  if (val < 44) return 'XL';
  if (val < 47) return 'XXL';
  return 'XXXL';
};

6.3 Digital Asset Preprocessing Pipeline (Python AI Studio Automation)

Raw garment captures often suffer from inconsistent backgrounds and lighting. An automated Python pipeline (batch_process_dress.py) standardizes all catalogue photography:

AI Studio Automation Steps
  1. Background Removal: Executes rembg using U2-Net deep learning models to isolate clothing contours.
  2. Bounding Box Crop & Centering: Automatically calculates tight garment bounding boxes and centers them on a 1000×1000 pure white (#FFFFFF) canvas.
  3. Photometric Enhancement: Enhances sharpness (factor 1.4) and contrast (factor 1.08) using Pillow (PIL.ImageEnhance).
  4. Soft Studio Drop Shadow: Extracts the garment's alpha mask, applies Gaussian blur (radius=15), scales opacity to 12%, and composites a downward 8px offset shadow.

6.4 Development Preview Engine (Offline Fallback)

When Supabase environment variables are absent, the application gracefully degrades into an isolated preview mode. It loads local sample fixtures (src/data/categories.js), stores test enquiries in localStorage, displays an informative banner, and safely disables administrative sign-in to prevent unauthorized actions.

8.2 Edge Hosting & Single Page Application Routing

The production build is hosted on Vercel's Global Edge Network. Because React Router 7 utilizes HTML5 pushState history, deep navigation URLs (such as /admin/products or /products/mens-crewneck) would trigger HTTP 404 errors on traditional static hosts when refreshed directly by a browser.

This is resolved by deploying a vercel.json rewrite configuration file in the project root: 

{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}

This configuration rewrites all incoming URI requests back to /index.html, enabling React Router 7 to inspect the browser location pathname and cleanly mount the corresponding component view.
